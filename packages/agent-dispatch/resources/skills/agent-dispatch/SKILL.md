# 委派给其他 CLI agent

## 铁律

**你是转发器，不是执行者。** 委派的意义是这次任务不消耗你的额度。所以：

- 不要为了写 prompt 去读仓库、grep、看文件。
- 不要自己先做一遍再对比。
- 不要总结、复述、加工返回结果——**原样贴回 stdout**。
- 收到结果后不要顺手接着改代码，除非用户又让你做。

用户让你委派，就只做一次 `ax` 调用。

## 流程

**1. 确定用哪个 agent —— 由用户拍板，不要替他选。**

用户没说用哪个就问。可以先 `ax list` 把可选项和各自的 effort 传法列给他看。

**2. 确定模型。**

用户点名了模型就直接用。用户只给了范围（"便宜快的"、"强一点的"），先 `ax list <agent>`
拿实时清单，挑两三个候选报给用户，等他确认再跑。不要自己拍板就执行。

**3. 写 prompt —— 必须自包含。**

被调 agent 没有本次对话的任何上下文。把文件路径、判断标准、完成条件都写进 prompt 里。
但这不等于你要去调研——用户描述得够清楚就直接转发他的原话。

**4. 执行。**

```
ax <agent> [--model M] [--effort E] [--write|--plan] [--resume] <prompt>
```

- 不传档位时不会改文件（各后端的默认档语义略有差别，`ax list` 里有写）。
  **只有用户明确要求改文件时才加 `--write`。**
- `--effort` 只有部分 agent 收，其余把档位编在模型编号里，`ax list` 会说明。传错了 `ax` 会
  直接报错并列出合法值。
- 拿不准命令拼得对不对，加 `--dry-run` 先看一眼，它只打印将要执行的命令，不真跑。

**5. 回贴。** stdout 原样给用户。它报错就把错误原样给用户，不要自己去排查。

## 边界

- 前台阻塞，没有后台任务。长任务就是会等。
- 不做工作区隔离，被调 agent 直接改当前工作树。要隔离得用户显式说，各 agent 的隔离能力
  不一样，`ax list` 里有注。
- 一次委派一个任务。不要串联多次 `ax` 调用去编排一个大任务——那是用户该拆的。
